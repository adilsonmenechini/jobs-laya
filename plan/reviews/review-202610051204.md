## Incidente pós-REVIEW: `security` do CI falhou (FAIL-IMPL corrigido)

O job `security` do PR #21 falhou com `leaks found: 1` — **após** o
`pre-commit run --all-files` local dar 11/11 verde.

- **Causa raiz:** o hook local roda `gitleaks git --staged` (diff staged); o CI
  roda `gitleaks dir .` (todo arquivo versionado). O `README.md` desta iteração
  trazia `INDEED_COUNTRY=BR`, que a regra `generic-api-key` casa sem validar
  formato de chave. O `develop` nunca disparou porque a linha era `INDEED_CO=`
  (3 chars, abaixo do corte de 4+).
- **Agravante:** o working tree carrega `.env` e `.claude/settings.local.json`
  untracked, que o CI nunca vê — localmente eram 3 findings, no CI 1 real.
- **Correção:** `INDEED_COUNTRY` → `INDEED_CO`, que é a variável que o código
  realmente lê (`app/sources/indeed.py:12`). O falso positivo apontava um **typo
  real**; corrigir pelo nome certo resolveu os dois de uma vez.
- **Verificado:** `gitleaks dir . --redact --no-banner` em **clone limpo** do
  branch → `no leaks found`. CI `security` verde no run seguinte.

Lição registrada em `plan/tasks/lessons-202610051204.md` (L4) e no AI Memory
(`notes/gitleaks-local-vs-ci.md`).
