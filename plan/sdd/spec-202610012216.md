# SPEC — Fontes Gupy e Glassdoor (202610012216)

## Objetivo

Adicionar duas novas fontes de vagas ao `JobSource` registry, seguindo o padrão
já estabelecido pelo GeekHunter (HTTP) e LinkedIn (browser):

1. **Gupy** — coleta via HTTP público (sem login, sem browser).
2. **Glassdoor** — coleta via browser local (Patchright), porque o site bloqueia
   HTTP direto (Cloudflare 403).

## Evidência de pesquisa (feito antes deste spec)

### Gupy
- Endpoint público e sem token: `GET https://portal.gupy.io/api/job-search/jobs`
  com `jobName`, `limit`, `offset` → `{data: [...], pagination: {total, limit, offset}}`.
- Filtros confirmados por experimento: `state=<nome completo do estado>` (ex.: "Bahia"
  devolve só BA), `city=<cidade>` (ex.: "Curitiba" devolve só Curitiba),
  `workplaceType=remote` (total cai de 7380 → 384 para o mesmo termo).
- Item já traz `description` completa (não truncada, ex.: 4059 chars), além de
  `name`, `careerPageName` (empresa), `workplaceType` (remote/hybrid/on-site),
  `city`, `state`, `publishedDate`, `jobUrl`, `id`.
- Página de detalhe (`<empresa>.gupy.io/job/<base64>`) é SSR e carrega
  `__NEXT_DATA__.props.pageProps.job.description` (HTML) — usado pelo `details()`
  apenas quando a busca veio sem descrição.

### Glassdoor
- HTTP direto → **403** ("Security | Glassdoor"). Só funciona com browser.
- Patchright headless consegue a SERP: `https://www.glassdoor.com/Job/jobs.htm?sc.keyword=X`
  redireciona (307→308) para `glassdoor.com.br/Vaga/...` e renderiza 30 vagas.
- A SERP é SSR-friendly: JSON-LD `ItemList` (position/name/url) + cards
  (`a[data-test="job-title"]`, `span.EmployerProfile_compactEmployerName`,
  `[data-test="emp-location"]`, `[data-test="descSnippet"]`, salary, `jl=<id>`).
- **Todas** as rotas de detalhe (`/job-listing/...`, `/partner/jobListing.htm`, e
  navegação SPA por clique) caem em desafio Cloudflare ("Um momento…" / "Somente
  humanos") no headless desta máquina, mesmo com referer, clique real e retry.
  Testado: goto direto, clique forçado, clique por coordenada, clique sintético,
  nova aba, referer explícito, retry — todos bloqueados.

## Requisitos funcionais

### FR-1 — Fonte Gupy (`app/sources/gupy.py`)
- `search(keywords, location, limit)` pagina por `offset` até `limit` itens.
- Mapeamento de `location` (proteção contra o gotcha do `cityName=remoto`):
  - vazio / `brazil` / `brasil` → sem filtro de local;
  - `remoto` / `remote` → `workplaceType=remote`;
  - nome completo de estado brasileiro (case-insensitive, 27 estados) → `state=`;
  - qualquer outra string → `city=`.
- Item normalizado: `source="gupy"`, `source_id=str(id)`, `title=name`,
  `company=careerPageName`, `location` ("Cidade - UF" ou vazio), `remote=
  (workplaceType == "remote")`, `url=jobUrl`, `description` (texto limpo de
  entidades HTML), `posted_at=publishedDate` (truncado em 100 chars, coluna do
  modelo), `raw` = payload cru.
- `details(item)`: devolve `item` se já houver descrição; senão busca `url` e
  extrai `job.description` do `__NEXT_DATA__` (fallback: mantém o item —
  partial-success).
- Erros de rede/HTTP → `SourceUnavailableError`.

### FR-2 — Fonte Glassdoor (`app/sources/glassdoor.py`)
- Browser-backed, com engine injetável (Protocol mínimo `goto/evaluate/wait`)
  para os testes rodarem sem browser real.
- `search(keywords, location, limit)`: monta a URL da SERP com `sc.keyword`
  (a localidade é Brasil inteiro — `location` é **ignorado** por esta fonte,
  documentado), navega, espera os cards e extrai:
  - `source_id` = `jl=<id>` da URL (ou path do `job-listing`),
  - `title`, `company`, `location` (cidade do card), `remote` = False
    (não há badge confiável na SERP; só texto), `url`, `description` = snippet +
    linha de "Habilidades:", `salary` no `raw`.
- Defesa: delay configurável entre navegações, timeout explícito,
  identificação de desafio (título "Um momento…" / "Somente humanos").
- `details(item)`: **retorna `item` inalterado** (limitação conhecida — ver
  Non-Goals). Nunca lança: partial-success por design.
- Falha de browser/navegação → `SourceUnavailableError` (o sync degrada a fonte
  em `errors["glassdoor"]` sem derrubar as outras).

### FR-3 — Registro e configuração
- `Settings` ganha: `gupy_base_url`, `gupy_delay_seconds`, `gupy_page_size`,
  `gupy_timeout_s`; `glassdoor_base_url`, `glassdoor_delay_seconds`,
  `glassdoor_timeout_ms`, `glassdoor_headless` (defaults em `.env.example`).
- `source_names()` e `build_sources()` passam a listar `gupy` e `glassdoor`
  (construídos só quando configurados, como o GeekHunter).
- `GET /jobs?source=` aceita `gupy` e `glassdoor` (regex do path atualizado).
- Dashboard (`app/static/index.html`): opções Gupy e Glassdoor nos dois selects
  (sync e filtro).
- README + `.env.example` atualizados.

### FR-4 — Testes (TDD — escritos antes do código)
- `tests/test_gupy_source.py`: busca paginada, mapeamento de location
  (remoto/estado/cidade/brazil), normalização do item, `details()` com e sem
  descrição, erro HTTP → `SourceUnavailableError` (httpx.MockTransport).
- `tests/test_glassdoor_source.py`: parser da fixture real da SERP
  (`tests/fixtures/glassdoor_search.html`) + busca via engine fake (sem browser)
  + desafio detectado → `SourceUnavailableError` / details sem efeito.
- Registry: `source_names`/`build_sources` com os novos nomes; regex de
  `source` na API; defaults de settings.

## Restrições

- Read-only: nenhuma escrita em provedor (Protocol `JobSource` intacto).
- Sem login, sem cadastro, sem API key, sem serviço pago.
- Sync parcial-success: uma fonte morta não pode derrubar as outras (padrão do
  PR #3).
- Suite de testes roda sem rede e sem browser real (fixtures + fakes).
- ruff check/format verdes; pre-commit verde.

## Non-Goals (explícito)

- **Descrição completa do Glassdoor**: toda rota de detalhe é bloqueada por
  Cloudflare no headless atual (evidência na seção de pesquisa). v1 usa o
  snippet da SERP. Futuro: Chrome real (`channel="chrome"`) ou modo headful.
- Filtro de localidade no Glassdoor (`location` ignorado — Brasil inteiro).
- Paginação da SERP do Glassdoor além da primeira página (30 vagas/página);
  a UI de paginação do Glassdoor é renderizada por JS com tokens efêmeros —
  fora do escopo da v1.
- Candidatura/apply em qualquer fonte.

## Critérios de aceite

1. `POST /jobs/sync` com `source: "gupy"` grava vagas classificadas sem browser.
2. `POST /jobs/sync` com `source: "glassdoor"` grava vagas (snippet) usando o
   browser local; se o browser falhar, responde 200 com `errors["glassdoor"]`.
3. `GET /jobs?source=gupy` e `?source=glassdoor` passam na validação e filtram.
4. `GET /health` lista todas as fontes configuradas.
5. `uv run pytest` e `uv run ruff check .` verdes; dashboard mostra as fontes.
