# SPEC — Laya fusion policy com confidence gating

- **Timestamp:** 202610022141
- **Branch:** fix/laya-fusion-policy
- **Status:** rascunho

## Contexto e objetivo

O eval revela que a política combinada (heurística + Laya 50/50) **piora** o classificador em 6/18 casos vs heurística pura (16/18 → 12/18). Causas raiz:
1. Laya erra `role_family` em casos limpos (SRE → `other`, contabilidade → `site_reliability`)
2. Laya ignora senioridade em PT-BR ("senior" no título → `seniority=0`)
3. Keyword spam engana Laya (marketing com cloud keywords → `platform_cloud`)
4. Thresholds 80/60 são rígidos; `devops-engineer-remote` cai 79.89 → medium

O objetivo é **adicionar confidence gating**: só confiar no Laya quando suas respostas têm alta confiança calibrada. Quando confiança baixa, cair para heurística.

## Requisitos

- R1: `LayaJobClassifier` deve usar `role_confidence`, `remote_confidence`, `skill_confidence` do `EngineResult` para ponderar a fusão (não 50/50 fixo)
- R2: Adicionar pergunta `exclusions` ao Laya (`questions.py`) para que o modelo aprenda a vetar dealbreakers
- R3: Thresholds 80/60 devem ter histérese (ex.: 78-82 zona de transição) ou serem configuráveis
- R4: Manter fallback automático para heurística quando Laya falha (já existe, não regressar)
- R5: `FakeEngine` deve retornar confianças realistas para testes continuarem passando

## Restrições e premissas

- Não mudar contrato de saída do classifier (`match`, `score`, `decision`, `reasons`, `gaps`)
- Não quebrar `CLASSIFIER_BACKEND=heuristic|fake|laya`
- `eval/evaluate.py` deve continuar rodando com os 3 screeners
- Checkpoint Laya (~800MB) não entra no CI; testes usam `FakeEngine`

## Casos de borda

- Laya retorna `role_confidence=0.0` (modelo incerto) → peso zero, heurística pura
- `exclusions` match no Laya mas não na heurística (ou vice-versa) → veto prevalece
- PT-BR jobs com `seniority=0` mas título tem "senior" → heurística deve prevalecer quando confiança baixa

## Riscos e decisões em aberto

- **Peso do gating:** linear? step function? sigmoid? Precisa experimentação no eval.
- **Nova pergunta `exclusions`:** Laya checkpoint atual não foi treinado com ela; pode degradar initially. Mitigação: peso baixo inicial, só vetar quando `exclusion_confidence > 0.8`.
- **Histérese vs configurável:** Histérese simples (ex.: high≥78, low≤62) evita flip-flop; configurável via env é mais flexível. Decidir no TASK.
