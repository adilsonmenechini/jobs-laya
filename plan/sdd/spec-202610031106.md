# SPEC — CLI `make skill` para criar skills locais

- **Timestamp:** 202610031106
- **Branch:** feature/skill-cli
- **Status:** rascunho

## Contexto e objetivo

Skills de agente vivem em `.claude/skills/<nome>/SKILL.md` (projeto) ou
`~/.claude/skills/<nome>/SKILL.md` (pessoal). Hoje criar uma é manual: abrir
o diretório, escrever o frontmatter (`name`, `description`) e o corpo.

O `search-jobs` foi criado assim nesta sessão — 120 linhas escritas à mão, com
o risco real de frontmatter inválido ou `description` fraca (é ela que o agente
lê para decidir quando acionar a skill).

**Objetivo:** um comando que crie o esqueleto de uma skill local com
frontmatter válido, para o agente preencher o corpo.

## Requisitos

- R1: `make skill NAME=<slug>` cria `.claude/skills/<slug>/SKILL.md` com
      frontmatter válido (`name` = slug, `description` = placeholder curto)
- R2: O comando **recusa** slug inválido (vazio, com espaços, caminho
      traversal como `../foo`, já existente) com mensagem clara — nunca sobrescreve
- R3: O comando **recusa** se `.claude/skills/` não existir, criando o
      diretório (não falha com "No such file or directory")
- R4: Após criar, mostra o caminho absoluto e o que preencher
- R5: `make skill-list` lista as skills do projeto com o `name` de cada uma
- R6: Nenhum teste roda em CI que dependa de skill criada pelo usuário

## Restrições e premissas

- **Somente escrita em `.claude/skills/`** — nunca em `~/.claude/`, nunca em
  `app/`, nunca em `plan/`. O comando não toca em código Python.
- Sem dependências novas: `make skill` é shell puro (o Makefile já é shell).
- O frontmatter `description` é placeholder — quem escreve é o agente. O comando
  **não** tenta gerar descrição automática.
- Skills são **locais por decisão do usuário** (2026-10-03): o `.gitignore`
  já cobre `codemap.md`, `.slim/`, `AGENTS.md`. **Fora de escopo** decidir se
  `.claude/skills/` entra no versionamento — isso é decisão sua, não do comando.

## Fora de escopo

- CLI em Python (`[project.scripts]`) — o Makefile já é a interface de comando
  do projeto (CLAUDE.md §2)
- Validar o corpo da skill (só o frontmatter)
- Publicar/linkar skills entre projeto e pessoal
- Qualquer comando que leia ou modifique `CLAUDE.md`

## Skills aplicáveis

- `plugin-authoring` — formato de `SKILL.md` e frontmatter (o `search-jobs` foi
  criado à mão nesta sessão; o risco de frontmatter inválido é real)
- `verification-planning` — TDD com os casos de recusa (R2/R3) antes da
  implementação

## Critérios de aceite

- [ ] CA1: `make skill NAME=deploy-guide` cria o arquivo com frontmatter válido
- [ ] CA2: `make skill NAME=deploy-guide` de novo → recusa com "já existe", não sobrescreve
- [ ] CA3: `make skill NAME=` / `NAME="foo bar"` / `NAME="../x"` → recusa com motivo
- [ ] CA4: `.claude/skills/` ausente → criado, skill criada
- [ ] CA5: `make skill-list` lista `search-jobs` e a recém-criada
- [ ] CA6: `make test` e `make lint` continuam verdes

## Casos de borda

- Slug com hífen/underscore (`deploy-guide`, `deploy_guide`) → válido
- Slug com maiúscula → recusar ou normalizar? **Decisão:** recusar, com dica de
  usar minúsculas (o `name` no frontmatter segue o padrão `kebab-case` das skills
  existentes)
- Nome reservado (`templates`) → recusar
- Diretório `.claude/skills` existe mas sem permissão de escrita → falha clara

## Riscos e decisões em aberto

- **Risco:** o agente rodar `make skill` e criar skills vazias que poluem a
  descoberta. **Mitigação:** o `description` placeholder é explicitamente
  marcado como "PREENCHER" — uma skill assim não descreve uso e o agente não a
  aciona por acidente.
- **Decisão em aberto:** `.claude/skills/` versionar ou não. Fora de escopo
  desta SPEC; o comando funciona dos dois jeitos.
