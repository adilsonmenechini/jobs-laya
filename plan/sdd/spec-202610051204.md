## Contexto e objetivo

A nota `PLAN-configuracao` pede a reestruturação do frontend do Job Classifier:
o menu lateral deve expor **apenas** Vagas, Kanban e Configurações, com Perfil e
Dados migrados para dentro de Configurações (abas), e Vagas como tela inicial.

O backend já cobre a maior parte da nota (Kanban, dedup idempotente, clean que
preserva cards, persistência em `kanban_jobs`) — verificado em `app/services/kanban.py`,
`app/main.py` e coberto por `tests/test_api_kanban.py` + `tests/test_api_clean.py`
(318 testes verdes no baseline). A lacuna real é **exclusivamente de navegação e
markup** do frontend estático (`app/static/`).

Decisões fechadas com o usuário nesta iteração:

- **Navegação:** hash router com sub-rotas — `#/vagas`, `#/kanban`,
  `#/configuracoes`, e deep-links `#/configuracoes/perfil` e `#/configuracoes/dados`.
  Compatível com o `currentRoute()` existente (regex `^#\/?`), sem rota nova no FastAPI.
- **Divisão de trabalho:** por arquivo, um dono por arquivo (OpenCode = `index.html`,
  OpenCode #2 = `app.js`, Pixel = testes + verificação Playwright), conforme a lição
  `agents-paralelos-mesmos-arquivos` da memória do projeto.

## Contrato de integração (fixado aqui — os dois implementadores DEVEM obedecer)

Qualquer mudança fora deste contrato é erro de integração, não estilo pessoal.

**Rotas do hash router**

| Hash | Página visível | Conteúdo |
|---|---|---|
| `#/vagas` (ou vazio) | `#page-vagas` | busca + filtros + lista (inalterado) |
| `#/kanban` | `#page-kanban` | 3 colunas (inalterado) |
| `#/configuracoes` | `#page-configuracoes` | tab Perfil ativa |
| `#/configuracoes/perfil` | `#page-configuracoes` | tab Perfil ativa |
| `#/configuracoes/dados` | `#page-configuracoes` | tab Dados ativa |

**Marcadores em `index.html`**

- Sidebar: exatamente 3 `.sidebar-link`, nesta ordem — `Vagas` (`#/vagas`),
  `Kanban` (`#/kanban`), `Configurações` (`#/configuracoes`).
- `#page-perfil` e `#page-dados` **não existem mais** como páginas. O conteúdo
  atual delas (form de perfil e painel de dados/clean) é movido para dentro de
  `#page-configuracoes`.
- Dentro de `#page-configuracoes`:
  - um elemento de abas com dois botões carrying `data-tab="perfil"` e
    `data-tab="dados"`;
  - dois painéis: `#tab-perfil` e `#tab-dados`,containing o conteúdo migrado.
- Nenhum seletor ou id existente usado pelos testes atuais pode sumir sem
  equivalente — em particular `id="profile-form"`, `id="clean-btn"`,
  `id="data-total"`, `id="source-counts"`, `id="jobs"`, e as colunas
  `id="kanban-CHECK|RUNNING|DONE"` com `id="kanban-body-<STATUS>"`.
  Esses ids **viajam** para dentro das abas; só o caminho muda.

**Contrato em `app.js`**

- `const PAGES = ["vagas", "kanban", "configuracoes"];`
- `currentRoute()` devolve `"vagas" | "kanban" | "configuracoes"`.
- O deep-link da tab é lido de `window.location.hash` (segmento após
  `#/configuracoes/`), com default `perfil`.
- `showPage()` continua marcando `.active` / `aria-current` pelo `href` — com
  `Configurações` ativo tanto em `#/configuracoes` quanto nas sub-rotas.
- `navigate()` chama `loadProfile()` quando a tab visível é `perfil` e
  `loadDataCounts()` quando é `dados` (hoje dispara pelo nome da página).
- Navegar para a mesma tab em hash diferente não pode gerar loop no `hashchange`.

## Casos de borda

- **Hash desconhecido** (`#/qualquer-coisa`) → cai em Vagas (comportamento já
  existente de `currentRoute()`, deve ser preservado).
- **Rota antiga** `#/perfil` / `#/dados` → não estão mais em `PAGES`, então caem
  em Vagas. É o comportamento desejado (CA10), e evita deixar links órfãos.
- **`#/configuracoes/`** com barra final → tab Perfil (default), sem erro.
- **Deep-link direto** para `#/configuracoes/dados` em carga nova: a tab Dados
  precisa carregar os contadores sozinha, sem depender de clique.
- **Troca de tab** trocando o hash: o `hashchange` recarrega os dados da tab
  destino e não duplica listener nem deixa a tab anterior visível.
- **Navegar para o mesmo hash** (clicar na aba já ativa) não deve gerar erro nem
  re-fetch desnecessário.
- **Voltar do browser** (back/forward) precisa refletir a tab certa.
- O `loadProfile()`/`loadDataCounts()` existentes dependem do perfil real em
  `data/profile.json` — que tem modificação não commitada na tree. Não sobrescrever.
