## L1 — Ao dividir trabalho por arquivo, todo arquivo que precisa ser editado precisa de dono

- **Padrão:** a divisão por arquivo fixou donos para `index.html`, `app.js` e
  `tests/test_dashboard.py` — mas não para `app/static/style.css`. O agente
  dono do HTML precisou estilizar as abas novas e, sem dono para o CSS,
  inlinou um bloco `<style>` dentro do próprio `index.html`.
- **Problema:** funciona e não quebra nada, mas foge do padrão do projeto
  (CSS em `style.css`) e cria dívida que sobra para a iteração seguinte.
- **Regra:** ao montar a tabela "1 arquivo = 1 dono", listar também os arquivos
  que a implementação **vai precisar tocar**. Se um arquivo necessário ficou sem
  dono, atribuir explicitamente — mesmo que a edição seja de 5 linhas.
- **Aplicável:** qualquer divisão de trabalho por arquivo entre agentes.

## L2 — Teste que fatia o HTML por seção vale mais que teste que busca o id solto

- **Padrão:** o assert "o id `profile-form` existe no documento" continuaria
  verde mesmo com a migração feita pela metade — bastava o id estar em qualquer
  lugar. O teste que realmente protegeu a mudança foi o que fatia o HTML entre
  `#page-configuracoes` / `#tab-perfil` / `#tab-dados` e afirmava que cada id
  está dentro do painel correto.
- **Regra:** quando um elemento **muda de lugar** no DOM, o teste precisa
  afirmar a nova localizeção, não apenas a existência. Existência global não
  detecta migração errada.
- **Aplicável:** refactor de markup, reorganização de telas, mudança de
  estrutura em qualquer árvore (HTML, JSON de config, AST).

## L3 — `hidden` + delegação evitam o listener-por-render e o loop de hash

- **Padrão:** a primeira tentação natural ao implementar abas é `addEventListener`
  dentro da função de render. Em SPA isso duplica listener a cada navegação e,
  se o clique reescrever o hash, dispara `navigate()` de novo — loop.
- **Regra:** o clique da aba escreve **apenas** em `location.hash`; o render é
  sempre via `hashchange` (fonte única de verdade). Delegation do listener uma
  única vez no load, não por render. E a aba já visível com o hash já alvo
  retorna cedo, antes de escrever no hash.
- **Aplicável:** abas, accordions, dropdowns, qualquer UIwhose state mora na URL
  em SPA hash-router.

## L4 — gitleaks local (`--staged`) não é o mesmo do CI (`dir .`)

- **Padrão:** o hook local roda `gitleaks git --staged` (só o diff staged); o job
  `security` do CI roda `gitleaks dir .` (todo arquivo versionado).
- **Problema:** o `pre-commit run --all-files` deu 11/11 verde e o `security` do
  CI falhou com `leaks found: 1`. A regra `generic-api-key` casa com qualquer
  linha `*_KEY=`/`*_COUNTRY=` de 4+ chars, sem validar o formato da chave — a
  linha de configuração `INDEED_COUNTRY=BR` disparou. O `develop` não disparava
  porque a linha era `INDEED_CO=` (3 chars, não casa).
- **Agravante:** o working tree carrega untracked (`.env`,
  `.claude/settings.local.json`) que o CI nunca vê, então rodar localmente suja o
  resultado — 3 findings locais vs. 1 real no CI.
- **Regra:** antes de declarar o PR verde, rodar **o comando exato do CI** em
  **clone limpo** (`git clone --depth 1` + `gitleaks dir .`). O byte count do
  output distingue as duas situações: ~4.6 MB = working tree, ~1.4 MB = clone.
- **Bônus:** o falso positivo apontava um **typo real** — o README documentava
  `INDEED_COUNTRY` e o código lê `INDEED_CO` (`app/sources/indeed.py`). Corrigir
  pelo nome certo resolveu os dois de uma vez. Antes de silenciar uma regra,
  verificar se o segredo apontado é real.
- **Aplicável:** qualquer validação de segurança que exista nos dois lugares
  (gitleaks, bandit) com escopo diferente entre hook e CI.
